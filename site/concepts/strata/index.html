A cross‑section of one encrypted record.

Type a message. a23crypt seals it in your browser, then this page cuts straight down through the result, layer by layer, with the real bytes. Four layers down, your message is still there, and nobody holding fewer than two keys can reach it.

      Survey notes

      Everything above ran in this tab with a JavaScript port of the wire format. The library itself is Python: four keyword-only functions, two for records up to 1 MiB and two for streams of any size in 64 KiB frames.

      Sealing a record

      import os, a23crypt

server_key = os.urandom(32)   # kept by your server
client_key = os.urandom(32)   # kept by your user

sealed = a23crypt.encrypt(
    b"The well is under the third oak.",
    server_key=server_key,
    client_key=client_key,
    record_key=b"map-0417",
    compress_level=3,   # optional zstd
)

a23crypt.decrypt(sealed, server_key=server_key,
                 client_key=client_key, record_key=b"map-0417")

# Files and sockets, in constant memory:
a23crypt.encrypt_stream(src, dst, server_key=..., client_key=..., record_key=...)

      Where the section ends

      • One leaked key weakens its layer.

        If server_key or client_key leaks, that party's protection is gone. The other still holds.

      • No replay detection.

        A valid ciphertext opens every time. Put a nonce or timestamp inside the plaintext if you need it.

      • Not a transport protocol.

        This is for records and files at rest. Use TLS for data in flight.

      • No password stretching.

        Run Argon2id yourself and pass in the 32-byte result.

      • No memory wiping.

        Decrypted bytes live on the Python heap and are not zeroed.

      • Streams can fail midway.

        A failed decrypt_stream may leave earlier chunks written. The bytes API is atomic.
